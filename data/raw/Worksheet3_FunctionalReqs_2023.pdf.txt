1. Actors
For each of the following systems, identify the actors, both human and non-human: 
(a) A word processor.
(b) An online retail website.
(c) A class registration system.
(d) An online mapping application.
(e) A set of traffic lights.
2. User Stories
For each of (b), (c) and (d) above, suggest four or more important user stories. Consider 
various human actors. 
For this purpose, pick user stories that each relate to a single functional requirement. (In general, 
user stories could relate to any requirement, but we’ll focus on functional requirements for now.) 
3. Developing Use Cases: Actor-goal list

of the selected system. Show them in an actor-goal list.

4. Developing Use Cases: Use Case Diagram 
Using the actor-goal list you have already created as the starting point, identify use 
cases and draw a use case diagram for the system you have selected in part 3 above. 
Consider the whole system when drawing the use case diagram. Your diagram should 
show all actors and significant use cases. 
You may not consider «include» relationships initially, but you may refine the created use 
case diagram to add «include» relationships. 
 
 
5. Developing Use Cases: Use Case Description 
Pick two of your user cases identified in part 3-4 above and expand them into complete 
use case descriptions (system-scope, user-goal-level). 
 
6. Additional Task 
Pick one of your user stories identified in part 2 above and convert/expand them into 
complete use case descriptions. 
First you can look at your user stories to identify the goals and actors. 
Then start producing the full description (system-scope, user-goal-level). 
 
 
End of Worksheet 
Note: Use case diagrams are a very broad picture of a system. They don’t show any 
details of a use case other than its name and the actors involved. For instance, the use 
case flow of events is not shown here. 
Any «include» relationships (arrows between use cases), if they exist at all, do not rep- 
resent time or order. Do not confuse use case diagrams with activity graphs. 
Drawing your diagrams by hand is sufficient for this exercise. You may try digital tools 
such as MS Visio, lucid charts(an on-line tool) also 
Note: Use case descriptions would have a header, flow of events and alternative flow of 
events sections. You can create a template of use case description with all required 
sections with headings as a table in a document and use it to develop use case 
descriptions. 
Note: There is no one to one mapping between user stories and use cases., however you 
may be able to identify use case relate to a user story or one or many user stories relate 
to a user case. 
Note: Some goals may have sub-goals also, but you are not expected to go to fine details 
at this lesson. 
Actor-goal list helps to identify use cases.
